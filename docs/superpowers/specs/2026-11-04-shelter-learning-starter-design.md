# Bay Area Shelter Hub — 교육용 시작 프로젝트 설계안

상태: 사용자 승인 완료. 2026-11-04 사용자가 subagent-driven-development 및 ponytail 방식으로 구현 시작을 요청했다.
작성일: 2026-11-04 (America/Los_Angeles)

## 1. 목적과 성공 기준

베이 에어리어 여러 보호소의 동물 정보를 한곳에서 검색하고, 해당 보호소의 공식 웹사이트나 연락처로 연결하는 웹사이트를 만든다. 입양·임시보호 신청과 처리는 보호소가 맡는다.

이번에 우리가 제공할 결과물은 **실행 가능한 교육용 시작 프로젝트와 학생 과제**다. 학생이 기능을 완성해 최종 검색 서비스를 만드는 것이 목적이다. 모든 검색 기능을 우리가 완성하는 프로젝트로 해석하지 않는다.

학생은 Java/Python을 배우고 있으며 현재 확인된 Java 학습 범위는 array, ArrayList, HashSet, HashMap이다. HTTP API와 Spring Boot는 처음이다. 클래스·메서드·객체 접근은 짧은 준비 수업과 제공 예제로 설명한다. 처음부터 Spring 설정, 비동기 통신, 프레임워크 생명주기까지 이해해야 하는 과제를 주지 않는다.

성공 기준:

- 설치·실행 안내를 따르면 Java 서버와 Python 화면이 실행되고 가상 동물 전체 목록이 표시된다.
- 학생이 작은 Java 메서드를 완성하면, 이미 연결된 화면에서 결과가 달라지는 것을 확인할 수 있다.
- 과제마다 요구사항, 수정 위치, 예시 입력·출력, 확인 방법, 힌트가 있다.
- 미완성 과제와 통신 오류, 검색 결과 없음이 명확하게 구분된다.
- 기본 목록에서 동물을 선택하면 해당 보호소 공식 페이지로 바로 이동한다. 상세 조회는 선택적인 학습 경로이며, 기본 사용자 흐름을 막지 않는다.

## 2. 사용자가 정한 조건

- 백엔드는 Java.
- 학생의 학습 경험을 고려해 화면도 최대한 Python으로 작성.
- 첫 지역은 SF, Mountain View, Santa Clara, San Jose 등을 중심으로 한 베이 에어리어.
- 실제 북부 캘리포니아 보호소 이름을 사용하고, 동물은 mock data로 구성.
- 사이트는 정보 탐색과 보호소 연결을 담당. 입양/foster 신청은 보호소에서 진행.
- 보호소 필터는 사용하지 않는다. 모든 보호소의 동물을 통합해서 보여주고, 동물 카드의 이름과 주 동작은 해당 보호소 공식 페이지로 바로 연결한다.
- 어려운 구조와 연결은 우리가 만들고, 세부 기능은 학생이 공부하며 구현.

## 3. 검토한 구현 방식과 선택

| 방식 | 장점 | 비용 또는 제약 | 결정 |
| --- | --- | --- | --- |
| Java Spring Boot + React/TypeScript | 다양한 웹 화면과 상호작용을 구성하기 좋음 | 학생에게 TypeScript 학습이 추가됨 | 선택하지 않음 |
| Java Spring Boot + Python NiceGUI | Java/Python으로 데이터 처리와 화면 역할을 나누어 학습 가능 | Java 서버와 Python 화면 서버 두 프로세스를 실행 | 사용자가 Java/Python 중심 진행을 선택함. NiceGUI는 제안한 화면 도구로 사용 |
| Java Spring Boot + Thymeleaf/HTML | Java 앱 하나로 서버와 HTML 제공 가능 | Python을 활용하는 학습 목표와 덜 맞음 | 선택하지 않음 |

기능을 가르치는 방식은 **작은 Java 컬렉션 과제 → API 흐름 설명 → Python 화면 과제** 순서를 제안한다. 처음부터 Java와 Python을 동시에 수정해야만 성공하는 과제는 피한다.

## 4. 이번 결과물의 범위

### 우리가 완성할 부분

- Java/Python 프로젝트 설정, 의존성 고정, 실행 및 종료 안내.
- Animal, Shelter 데이터 모델과 읽기 전용 mock 데이터 로딩.
- API 경로와 JSON 형식, 입력 검증, HTTP 오류 변환.
- Python의 비동기 HTTP 통신, 연결 시간 제한, 화면 갱신과 오류 표시.
- 전체 동물 목록을 Java에서 받아 Python에 표시하는 완성 예제.
- 학생 과제용 메서드의 입력·출력 정의와 호출 위치.
- 필터 입력, 목록, 상세 정보 경로의 기본 화면 연결. 미완성 기능은 학습 과제로 명확히 안내.
- 보호소 공식 사이트 링크와 연락처, 데모 표시.
- 기본 동작 검증, 과제 확인용 테스트, 학생용 안내, 교사용 수업 진행 안내.

### 학생에게 남길 부분

- 종류·최대 나이 조건에 따른 Java 필터링.
- HashMap을 활용한 동물 ID 조회.
- 단계가 진행된 뒤 이름/품종 검색 및 입양/임시보호 조건.
- Java 과제 이후 Python에서 상세 정보의 한 부분을 직접 구성하는 화면 확장 과제.
- 각 단계의 추가 테스트 사례 작성과 결과 설명.

### 이번에 포함하지 않는 부분

- 실제 보호소 데이터 수집, 크롤링, 자동 갱신, 외부 데이터 API 연동.
- 입양/임시보호 신청서, 로그인, 계정, 결제, 채팅.
- 데이터베이스, 지도, GPS, 거리 계산, 알림, 즐겨찾기, 페이지네이션.
- 클라우드 배포와 외부 공개. 우선 로컬에서 실행하고 학습한다.
- 학생 과제의 정답 구현. 요청이 있으면 나중에 별도 교사용 자료로 작성한다.

## 5. 단순한 구조와 책임

브라우저 ↔ Python NiceGUI 화면 서버 → Java Spring Boot JSON API → 메모리에 읽어 둔 mock 데이터.

검색·조회 규칙은 Java에 둔다. Python은 입력값을 보내고 결과를 표시한다. Python에서 같은 필터 규칙을 다시 구현하지 않는다. API와 프레임워크 코드는 학생 과제 코드와 분리한다.

Java는 데이터 모델, 데이터 로딩, API 처리, 학생용 검색 로직으로 필요한 만큼만 나눈다. 다수의 서비스 계층이나 플러그인 구조를 만들지 않는다. 학생이 초기에 수정하는 Java 파일은 1~2개 이내로 제한한다. 기본 풀이에는 for문, if문, 이미 배운 컬렉션을 사용한다. Stream, 람다, 디자인 패턴을 필수로 요구하지 않는다.

Python은 화면과 API 통신 코드를 분리한다. 통신은 화면 이벤트 루프를 막지 않게 우리가 구현한다. 연결 실패와 제한 시간 초과는 사용자에게 설명 가능한 상태로 변환한다.

위 공식 페이지를 2026-11-04 세션에서 확인했다. 구현 시 실제로 사용할 공식 URL·전화번호는 해당 공식 페이지의 값으로 고정하고 출처를 함께 기록한다. Mountain View라는 검색 대상 지역과 보호소 시설의 실제 소재지를 혼동하지 않는다. 없는 Mountain View 시설을 만들어 표시하지 않는다.

동물 필드: mock 식별자, 이름, 종류(DOG/CAT), 품종 설명, 나이(개월), 짧은 소개, 사진 경로 또는 빈 값, 보호소 ID, 입양 가능 여부, 임시보호 가능 여부, 데모 표시.

보호소 필드: ID, 공식 이름, 실제 소재 도시, 공식 웹사이트/입양 안내 URL, 공식 일반 문의 전화번호, 출처 URL.

나이는 0 이상의 정수이며, 이번 mock 데이터에는 나이 미상 사례를 넣지 않는다. 품종은 샘플 설명이다. 동물 사진은 로컬 데모용 그림 또는 적법하게 사용할 수 있는 샘플 이미지와 대체 이미지를 사용하며 실제 보호 동물 사진을 수집하지 않는다.

전체 화면과 상세 정보에 가상 동물이라는 안내를 유지한다. 보호소와 제휴했다고 표현하지 않는다. 링크는 보호소 일반 안내/입양 안내로 연결하며, mock 동물의 실제 등록 페이지가 있다고 주장하지 않는다. 이 링크로 가상 동물의 입양을 문의하도록 유도하지 않는다.

## 7. 학생 과제의 단계와 동작 기준

모든 단계에서 기존 입력 컬렉션을 변경하지 않는 것을 기본 규칙으로 한다. 첫 수업에 우리가 원본과 결과 ArrayList의 차이를 설명한다. 구현 계획에서는 각 과제를 정확한 파일·메서드·테스트에 연결한다.

| 단계 | 학생 구현 | 사용 지식 | 완료 기준 |
| --- | --- | --- | --- |
| 준비 | 제공된 Animal 객체의 이름을 읽고 목록을 반복 출력 | 객체와 메서드 사용의 짧은 예제, for문 | 샘플 한 마리와 여러 마리의 데이터를 읽을 수 있음 |
| 1 | 종류가 일치하는 동물들을 새 ArrayList에 담기 | for, if, ArrayList | DOG/CAT 조건과 0건 결과가 정확하고 원본 목록이 유지됨 |
| 2 | 최대 나이 이하인 동물들을 고르기 | 숫자 비교, ArrayList | 24개월 이하에 24개월은 포함, 25개월은 제외; 0개월 경계 확인 |
| 3 | ID를 키로 한 HashMap 구성 및 조회 | HashMap.put/get | 존재하는 ID는 해당 동물, 없는 ID는 null; HTTP 404 변환은 제공 코드가 담당 |
| 4 · 심화 | 이름/품종 검색, 입양/임보 조건 추가 | 문자열 처리, 조건 조합 | 검색어 공백 정리·대소문자 무시; 입양과 임보 가능 여부를 각각 확인 |
| 5 · 후속 | 상세 정보에 입양·임보 가능 여부 안내 영역 추가 | Python 함수, 딕셔너리, if, NiceGUI 요소 | Java 응답으로 화면 문구를 만들며 Java 검색 규칙을 중복 구현하지 않음 |

첫 과제는 교사와 함께 끝내고, 이후 같은 구조의 과제를 학생이 주도하도록 제안한다. 단계 4~5는 기본 1~3단계를 이해한 뒤 진행한다. HashSet을 사용시키기 위해 별도 제품 기능을 추가하지 않는다. 수업 횟수와 기간은 고정하지 않는다.

테스트는 정답 출력만 외우는 작업이 되지 않도록, 각 과제에 대표 예시를 제공하고 학생이 경계 사례 하나를 추가하도록 한다. 기본 테스트 실행법은 우리가 설정한다. 예외 테스트나 MockMvc 설정 자체를 첫 과제로 주지 않는다.

## 8. API와 미완성 기능의 계약

- 전체 목록: `GET /api/animals`, 응답은 `items` 배열과 `total` 개수. 처음부터 동작.
- 보호소 목록: `GET /api/shelters`, 응답은 `items` 배열. 처음부터 동작.
- 상세 조회: `GET /api/animals/{id}`. 학생의 ID 조회 과제를 호출.
- 목록 조건: `species`, `maxAgeMonths`, `q`, `purpose`. 보호소 선택 파라미터는 제공하지 않는다.
- `species`: DOG/CAT. `purpose`: ADOPT/FOSTER. 잘못된 값과 음수/정수가 아닌 나이는 400.
- 조건 미지정은 해당 필터를 적용하지 않음. 빈 검색어는 검색 조건 없음으로 처리.
- 서로 다른 종류의 검색 조건끼리는 모두 만족해야 함.
- `total`은 필터링된 전체 개수. 페이지네이션은 하지 않음. 결과의 기본 순서는 데이터 파일 순서.
- 학생 코드가 없는 기능은 과제 ID를 포함한 전용 예외를 발생시킴. 제공된 API 코드가 `501`과 `EXERCISE_NOT_IMPLEMENTED` 오류 코드로 바꾸고, 화면은 구현할 과제를 안내.
- 미완성 기능을 빈 결과, 성공 응답, 조용히 무시되는 필터로 처리하지 않음.
- 학생 과제에 없는 예상치 못한 서버 오류는 일반 서버 오류로 처리. 모든 오류를 과제 미완성으로 바꾸지 않음.
- ID 조회 구현 후 실제 존재하지 않는 ID는 404. 검색에 일치하는 동물이 없으면 정상 200과 빈 `items`.

기본 목록은 과제 메서드의 미완성 여부와 무관하게 작동한다. 학생이 메서드를 완성하면 같은 호출 경로가 결과를 표시하므로 별도의 기능 활성화 설정을 수정할 필요가 없다. 오류 JSON 필드와 정확한 메서드 시그니처는 구현 계획에서 고정한다.

## 9. 실행·검증·교육 자료

시작 프로젝트 검증과 학생 과제 채점은 실행 명령을 구분한다. 시작 프로젝트 검증은 정상 목록 표시·JSON 구조·입력 검증·연결 오류 처리를 확인하고 통과해야 한다. 미완성 과제의 결과 테스트는 별도 명령으로 실행하며 실패 이유가 과제 문서에 명시되어야 한다. 구현하지 않은 과제를 성공으로 보고하거나 기본 검증을 항상 실패 상태로 두지 않는다.

학생 안내는 한국어, 사용자 화면은 미국 대상 서비스에 맞춰 영어를 제안한다. 데모와 미완성 과제 안내도 명확하게 작성한다. 처음에는 localhost에서만 실행한다. 두 서버 실행·종료, 포트 충돌, Java 서버가 꺼졌을 때의 확인 방법을 안내한다.

교사용 문서는 준비 수업, 과제 순서, 관찰할 오개념, 힌트 순서와 완료 기준을 담는다. 정답 코드는 포함하지 않는다.

구현 환경 사전 확인: 현재 `python3`는 3.13.9이며 `java -version`으로 사용할 Java 런타임을 찾지 못했다. 구현 계획에 JDK 준비와 버전 확인을 포함한다. 이 사실을 근거로 이미 Java 실행을 검증했다고 주장하지 않는다. 구체적 JDK·Spring Boot·NiceGUI 및 빌드 도구 버전은 계획 단계에서 공식 호환성 확인 후 고정한다.

## 10. 설계자의 제안과 구현자에게 남긴 선택

승인된 초기안: 5개 보호소/20마리, 단계별 과제 순서, 한국어 학습 문서/영어 화면, 로컬 실행, DB 없는 시작, 정답 코드 미제공.

구현자 재량: 이름/패키지/파일의 구체적 배치, 유지보수되는 호환 버전 선택, 단순한 색상과 여백, 테스트 프레임워크 세부 설정, 로컬 샘플 이미지 방식. 선택은 구현 계획에 기록하며, 공개 배포나 새 기능을 추가하는 권한으로 확대하지 않는다.

작업은 교육용 웹 프로젝트다. 승인된 설계를 구현 계획으로 구체화하고, 사용자가 지정한 subagent-driven-development 방식으로 실행한다. 사용자의 구현 시작 지시에 따라 추가 진행 확인 없이 작업과 검증을 이어간다.
